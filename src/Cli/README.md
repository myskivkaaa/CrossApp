# CrossApp
Наскрізний проєкт з крос-платформного програмування.

Предметна область: Склад. 
Сутності: Product (товар), StockBatch (партія), Warehouse (склад), Movement (переміщення). 
Призначення: облік залишків товарів по партіях.

## Запуск
dotnet build
dotnet run --project src/Cli

## Інваріанти доменної моделі (Лабораторна робота 4)
Обов'язковий рядковий ключ: Поля Id та Sku не можуть бути порожніми чи складатися лише з пробілів (ArgumentException).

Коректність кількості: Початковий залишок при створенні та значення для приходу/видачі мають бути невід'ємними / більшими за нуль (ArgumentOutOfRangeException).

Контроль стану складу: Неможливо видати більшу кількість товару, ніж є на поточному залишку (InvalidOperationException).

Переходи статусів: Статус товару може змінюватися лише за допустимими бізнес-правилами через switch expression (з Draft у Active/Discontinued).

## Архітектура сервісного шару та сховищ (Лабораторна робота 5)
Інтерфейс сховища (ICatalogStore): Абстракція над способом зберігання даних (методи List, GetById, Add, Update, Remove, FindBy).

Реалізації сховищ:

InMemoryCatalogStore (робота в оперативній пам'яті на основі Dictionary).

FileCatalogStore (зберігання на диск у форматі JSON з кешуванням та дозавантаженням).

Декоратор (CachingCatalogStore): Огортає інше сховище для оптимізації доступу через локальний кеш у пам'яті.

Сервісний шар (CatalogService): Інкапсулює бізнес-операції та залежить виключно від абстракції (ICatalogStore) через ін'єкцію в конструкторі.

Composition Root: Точка входу в Program.cs, де за допомогою аргументів командного рядка (--file, --cache) або фабрики StoreFactory створюються та зв'язуються конкретні об'єкти.

## Лабораторна робота №6: Доменні події, делегати Action/Func, лямбди

### Реалізований функціонал:
1. **Доменні події у `Core`**: 
   - Створено `enum CatalogChangeKind` (`Added`, `Received`, `Issued`, `Removed`)
   - Створено клас даних події `CatalogChangedEventArgs` (успадкований від `EventArgs`)
   - Додано подію `event EventHandler<CatalogChangedEventArgs>? Changed` у `CatalogService` та приватний метод підняття `OnChanged` після успішних операцій
2. **Підписки в `Cli`**:
   - Підписано локальний метод `OnCatalogChanged`, який виводить події в консоль та записує їх у файл `logs/app.log`
   - Додано другого підписника у вигляді лямбда-виразу із замиканням над лічильником `changes`
   - Продемонстровано відписку (`-=`) та сценарій відмови (коли виняток зупиняє підняття події)
3. **Використання `Func`**:
   - Реалізовано метод `FindAll` (і `FindBy`) із сигнатурою `Func<Product, bool>` для гнучкої фільтрації даних
4. **Додаткові завдання**:
   - Реалізовано інтерфейс `INotificationSink` з альтернативними реалізаціями `ConsoleSink` та `FileSink`.
   - Додано метод імпорту `ImportProducts` із параметром `Action<string> reportSkipped` для обробки помилок імпорту..

## Коли виконується запит і чому Count() дає різні результати:
У нашому коді оператори LINQ (такі як Where чи Select) побудовані на базі відкладеного виконання (Deferred Execution), тому вони не обробляють дані в момент їх оголошення. Запит реально запускається лише тоді, коли відбувається перебирання елементів або викликається завершальний оператор на кшталт Count() чи ToList(). Саме тому два виклики query.Count() до і після додавання нового елемента до джерела дали різні числа: під час другого виклику запит перерахував уже оновлену колекцію.

### Лаб7
Відкладене виконання (Deferred Execution): Оператори LINQ (Where, Select) не виконуються в момент їх оголошення, а запускаються під час ітерації чи виклику завершальних методів на кшталт Count(). Саме тому виклики Count() до і після зміни джерела дають різні результати.   
   Порівняння синтаксису запитів: Методний синтаксис (Method Syntax) використовує ланцюжки лямбда-виразів і є зручнішим для динамічних запитів, тоді як синтаксис запитів (Query Syntax) нагадує SQL і є більш читабельним при складному групуванні чи об'єднанні даних.

# Профілі конфігурації
* **Development** (за замовчуванням): використовує `appsettings.json` та `appsettings.Development.json` з детальним рівнем логування (`MinimumLevel: Debug`).
* **Production**: призначений для розгорнутого застосунку, де налаштування та секрети передаються через змінні середовища ОС або спеціалізовані сховища.
